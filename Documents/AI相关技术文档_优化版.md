# AI 相关技术文档（优化版）

本文档为非技术背景人员编写，旨在解释系统中涉及的核心 AI 概念、工作流及其实现细节。

---

## 1. 基础概念层：数据预处理

> **PDF 解析**
>
> 论文通常是以 PDF 格式存储的。系统通过 `PyPDF` 等专用工具分析 PDF 的文本内容。在解析完成后，提取的文字会存入数据库，并进行后续的“切块”和“向量化”。

> **切块 (Chunking)**
>
> 将长篇幅的文本拆分为若干小段落。为了保证上下文语义的连贯，通常两个相邻的段落之间会保留一部分重复内容。
>
> **示例演示**：
> *   **切块前**：*“小明是一个18岁，性别为男的某高等中学的某个班级的学生。”*
> *   **切块后**：`[小明是一个]`，`[一个18岁]`，`[性别为男的]`，`[某高等中学]`，`[中学的某个班级]`...
>
> *注：切块通常由专门的算法包完成。*

## 2. 向量技术：让计算机“读懂”文字

> **向量 (Vector)**
>
> 向量在数学上是一组数字（如 `[0.1, 0.2, -0.3, 0.8]`）。在 AI 领域，它是计算机理解人类语言的一种“数学坐标”。
>
> *   **相关性判断**：通过计算两组向量之间的“距离”（如欧式几何算法），可以判断它们的语义是否相关。**距离越近，相关性越高。**

> **向量化 (Embedding)**
>
> 核心过程。通过一个被训练好的**嵌入模型 (Embedding Model)**，将一段自然语言（中英文等）转化为一组向量。

> **向量数据库 (Vector Database)**
>
> 专门存储并支持向量计算的数据库。在我们的系统中，数据库支持向量扩展功能。
> *   **数据表结构简析**：`id | 向量数据 | 切块原文内容 | 额外信息（如论文 ID、切块编号）`。

> **向量检索 (Vector Retrieval)**
>
> 当用户提问时，系统先将提问也转化为向量，然后在向量数据库中运行数学算法，找出语义相似度最高的若干条“原始数据块”。

## 3. RAG：检索增强生成

> **什么是 RAG (Retrieval-Augmented Generation)？**
>
> RAG 是“向量检索”与“大语言模型 (LLM)”的组合拳。它将用户输入先拿到数据库里搜一下，搜到相关的“证据”后再丢给大模型进行回答。
>
> **RAG 工作流示意：**
>
> ```mermaid
> graph LR
> A[用户提问] --> B[嵌入模型]
> B --> C{向量检索}
> C --> D[(向量数据库)]
> D --> C
> C --> E[找出的相关论文片段]
> E --> F[大模型 LLM]
> F --> G[最终生成的回答]
> ```

## 4. LLM 模型能力与工具系统

> **LLM (Large Language Model)**
>
> 本系统使用的大语言模型具备三大核心能力：
> 1.  **自然语言生成**：像人类一样交流、归纳、回答问题。
> 2.  **结构化输出**：强制模型输出符合特定格式（如 JSON）的数据。
> 3.  **工具调度**：当模型需要额外资源（如查数据库、搜网）时，主动请求调用外部程序。

> **工具 (Tool) 的构成**
>
> 1.  **声明部分 (JSON)**：包含工具名、描述、参数格式等，用于“告诉”大模型该工具有什么用。
> 2.  **实现部分 (Python)**：实际运行的后台代码，负责具体的数据处理。

> **工具调度与 JSON 数据结构**
>
> 当大模型决定使用工具时，它会输出一段 JSON。系统框架解析这段数据，并自动执行对应的函数，反馈执行结果给模型。
>
> **示例 JSON 结构**：
> ```json
> {
>   "name": "search_web",
>   "description": "搜索网络信息",
>   "args": { "search_key": "string" }
> }
> ```

## 5. Agent 智能助手体系

> **Agent (代理/智能体)**
>
> 指具备主动调度资源（获取数据库、网络等外部信息）能力的 AI 模块。通常通过“绑定工具”实现。

### 系统中的典型 Agent 实现：

1.  **ChatAgent (对话助手)**：
    *   **核心功能**：具备向量搜索工具，通过检索数据库内容来回答论文相关问题。
    *   **精准锁定**：系统会自动在工具参数中传入“当前阅读论文的 ID”，确保助手不会搜到无关的论文。
    *   **决策机制**：`用户提问` -> `Agent 判断是否需检索` -> `是：执行检索 -> 获取数据 -> 判断是否够了` -> `否：最终输出回答`。

2.  **MindMapAgent (脑图助手)**：
    *   **核心功能**：利用结构化输出能力，将解析后的论文核心论点生成特定格式数据。
    *   **数据流**：论文解析完成 -> 触发 Agent 生成脑图 -> 存入数据库 -> 前端实时更新展示。

3.  **Summary (总结助手)**：
    *   **核心功能**：纯提示词驱动，在论文导入时自动提取全文核心摘要。

## 6. 实时体验：流式传输 (SSE)

> **流式输出 (Streaming)**
>
> 类似于 ChatGPT，内容是一个字一个字蹦出来的，而不是等全部生成完再显示，极大地缓解了等待焦虑。

> **SSE (Server-Sent Events) 技术**
>
> 后端主动向前端推送消息的技术。与普通请求相比，它建立了一个持续的“数据通道”。
>
> *   **连接阶段**：前端打开通道，建立长连接。
> *   **输出阶段**：后端按预定结构（包含 `id`, `event`, `context` 等）持续推送字符。
> *   **结束阶段**：生成完毕，前端关闭连接。

### SSE 后端输出类型示例：

| 事件类型 (Event) | 描述 | 数据示例 (Context) |
| :--- | :--- | :--- |
| `chat` | 文本逐字输出 | `你好` / `我叫` / `小明` |
| `tool` | 工具调度信息 | `{"id": "1", "name": "search", ...}` |
| `end` | 传输完成 | `(空)` |
