# 变更日志: 统一翻译与备注的交互模型

**提交人**: FrontendAgent(react)
**日期**: 2026-01-25 22:30:00

## 变更背景
推翻之前的设计决策（将翻译作为独立的 `translate` 类型）。
用户反馈“点击无翻译”以及需要“重新思考”，经过分析，核心痛点在于：
1.  **交互不一致**: 之前的设计将翻译作为只读类型，不支持悬浮预览（Tooltip），也不支持用户编辑修正翻译结果。
2.  **功能割裂**: 用户希望翻译结果可以像备注一样被管理、查看和悬浮显示。

## 变更内容

### 1. 统一数据模型
- **文件**: `src/components/reader/PDFPageOverlay.tsx`
- **修改**: `handleSaveTranslationAsNote` 重新接管保存逻辑。
- **逻辑**: 
  - 新的翻译结果将统一保存为 `type: 'note'`。
  - 使用 **绿色** (`bg-green-300`) 来在视觉上区分翻译备注和普通备注。
  - 内容格式保持 `[原文] ... [译文] ...` 以便阅读。

### 2. 增强悬浮预览 (Tooltip)
- **文件**: `src/components/reader/PDFPageOverlay.tsx`
- **修改**: 扩展 Tooltip 的触发条件，现在支持：
  - 标准 `note` 类型。
  - 遗留的 `translate` 类型（兼容旧数据）。
  - 智能识别内容：如果内容包含 `[译文]`，Tooltip 标题会自动显示为“翻译”并使用绿色图标，否则显示“备注”。
- **效果**: 用户鼠标滑过绿色的翻译虚线时，会直接浮层显示翻译结果，无需点击。

### 3. 恢复编辑能力
- **影响**: 由于翻译现在是 `note` 类型，点击高亮区域将弹出标准的备注编辑框。
- **优势**: 用户可以自由修改翻译结果（例如修正机翻错误），或在翻译下方添加自己的理解。

## 验证
- **场景1**: 翻译 -> 保存 -> 出现绿色高亮 -> **鼠标悬停** -> 显示翻译预览（解决痛点）。
- **场景2**: 点击绿色高亮 -> 弹出编辑框 -> 可以修改文本 -> 保存 -> 预览更新。
- **场景3**: 兼容性测试 -> 之前创建的 `translate` 类型高亮仍然可以正常显示 Tooltip（代码已做兼容）。
